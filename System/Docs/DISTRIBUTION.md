# نقل النسخة النظيفة إلى جهاز آخر

1. من نسخة التطوير شغّل BUILD_DISTRIBUTION.bat، واختر الأدوات فقط أو تضمين توزيعات System/Bin المحلية الكاملة.
2. ينتج مجلد و ZIP داخل dist؛ لا تُحذف الاختبارات أو النسخ الاحتياطية من المستودع.
3. انقل المجلد كاملًا أو فك ZIP على Windows 10/11 في مجلد قابل للكتابة.
4. شغّل START_HERE.bat. الاعتمادات المحلية لها الأولوية، ثم المثبتة، ثم تنزيلات اختيارية متحقق منها.
5. إن كانت الاعتمادات موجودة محليًا تعمل الأدوات دون إنترنت. التوزيع الخالي من البرامج يحتاج تجهيزًا عند الجهاز الآخر.
6. اقرأ MD الخاص بالأداة، وضع الملفات في Input واستلم النتائج من Output.

التوزيع يضم الأدوات وشرحها وملفات التشغيل المشتركة الضرورية و README وسجل الاعتمادات؛ لا يضم .git أو Development أو System/Downloads أو تقارير التطوير أو ملفات المستخدم في Input/Output/Watermark. مجلدات التشغيل تُنشأ فارغة داخل ZIP أيضًا.

ملف distribution-manifest.json يسجل SHA-256 لمحتوى كل ملف قبل كتابة manifest نفسه. لا يحفظ صلاحيات NTFS أوالملكية أو Alternate Data Streams، وليس صورة نظام. القابلية للنقل لا تمنح تلقائيًا حق إعادة توزيع برامج الطرف الثالث؛ راجع DEPENDENCIES.md.

البرامج المثبتة خارجيًا لا تُضم تلقائيًا. START_HERE.bat --portable يعرض نسخ شجرة البرامج المثبتة الكاملة إلى System/Bin بعد الموافقة لكل برنامج؛ بعدها يمكن إعادة البناء مع تضمينها. إذا تعذّر تحديد مجلد التوزيعة بأمان، يُحفظ الوضع السابق وتظهر إرشادات التجهيز اليدوي.

في نسخة100 أداة يشمل System/Shared وظائف PDF وOCR الصغيرة وفهرس اللغات المثبت. يحتفظ التوزيع بمجلد Corners فارغًا للماسح، وLeft/Right للمقارنة، ولا يدخل أي ملف خاص من مدخلات المستخدم. عند نقل نسخة التطوير كاملة يمكن الاحتفاظ بـSystem/Bin للعمل دون إنترنت بعد مراعاة التراخيص؛ أما ZIP الافتراضي فيحتاج فحص وتجهيز START_HERE على الجهاز الآخر.
