## ⭐ أفضل أمر للاستخدام اليومي

```bash
ffmpeg -i input.mp4 -c:v libx264 -crf 23 -preset medium -c:a aac -b:a 128k -movflags +faststart output.mp4
```

### ماذا يفعل؟

- `-i input.mp4` → الفيديو الأصلي.
    
- `-c:v libx264` → يستخدم H.264 لضغط الفيديو.
    
- `-crf 23` → مستوى جودة الفيديو.
    
- `-preset medium` → توازن بين سرعة الضغط وحجم الملف.
    
- `-c:a aac` → ضغط الصوت باستخدام AAC.
    
- `-b:a 128k` → جودة الصوت 128 kbps.
    
- `output.mp4` → اسم الملف الناتج.
    

## 🚀 `-movflags +faststart`

```bash
-movflags +faststart
```

يُستخدم مع ملفات **MP4** لتحسين تشغيل الفيديو عبر الإنترنت.

### ماذا يفعل؟

ينقل معلومات الـ **Metadata / MOOV Atom** من نهاية ملف الفيديو إلى بدايته.

وبالتالي:

- ▶️ يبدأ الفيديو بالتشغيل بشكل أسرع أثناء التحميل.
    
- 🌐 مناسب جدًا للفيديوهات التي ستُرفع على Website.
    
- 📱 مفيد للبث والتشغيل التدريجي عبر الإنترنت.
    
- 📦 لا يضغط الفيديو ولا يغيّر جودة الصورة.
    
- ⏱️ قد يضيف وقتًا بسيطًا جدًا بعد انتهاء عملية الترميز لإعادة ترتيب الملف.
    

### مثال

```bash
ffmpeg -i input.mp4 -c:v libx264 -crf 23 -preset medium -c:a aac -b:a 128k -movflags +faststart output.mp4
```

### ⭐ القاعدة السريعة

```text
فيديو للاستخدام المحلي فقط
→ اختياري

فيديو للموقع / الإنترنت
→ يُنصح باستخدامه ⭐
```

> **ملاحظة:** `-movflags +faststart` لا يقوم بعملية ضغط بحد ذاته؛ وظيفته تحسين ترتيب ملف MP4 ليكون مناسبًا أكثر للتشغيل عبر الإنترنت.

# 🚀 H.265 / HEVC

إذا كنت تريد حجمًا أصغر مع جودة جيدة:

```bash
ffmpeg -i input.mp4 -c:v libx265 -crf 26 -preset medium -c:a aac -b:a 128k output.mp4
```

### H.265 مقارنة بـ H.264

**H.265:**

- حجم أصغر عادةً
    
- كفاءة ضغط أفضل
    
- أبطأ في الترميز
    
- توافق أقل في بعض الأجهزة والأنظمة
    

**H.264:**

- توافق ممتاز جدًا
    
- أسرع
    
- مناسب للمواقع والمشاركة
    
- الخيار الآمن لمعظم الاستخدامات
    

### ⭐ القاعدة

```text
أقصى توافق → H.264
أصغر حجم → H.265
```

# ⚡ NVIDIA GPU — NVENC

إذا كان لديك **NVIDIA GPU**، يمكنك استخدام كرت الشاشة لتسريع عملية ترميز الفيديو باستخدام **NVENC**.

> **NVENC** هو Hardware Encoder مدمج في بطاقات NVIDIA، ويقوم بعملية ترميز الفيديو باستخدام الـGPU بدل الاعتماد بشكل أساسي على الـCPU.

---

## 🎬 H.264 NVENC

```bash
ffmpeg -i input.mp4 -c:v h264_nvenc -cq 23 -preset p5 -c:a aac -b:a 128k -movflags +faststart output.mp4
```

### ماذا يفعل؟

- `-i input.mp4` → الفيديو الأصلي.
    
- `-c:v h264_nvenc` → استخدام NVIDIA NVENC لترميز الفيديو بصيغة H.264.
    
- `-cq 23` → مستوى جودة الفيديو باستخدام Constant Quality.
    
- `-preset p5` → مستوى سرعة/كفاءة الترميز.
    
- `-c:a aac` → ضغط الصوت باستخدام AAC.
    
- `-b:a 128k` → جودة الصوت 128 kbps.
    
- `-movflags +faststart` → تحسين تشغيل MP4 عبر الإنترنت.
    
- `output.mp4` → ملف الفيديو الناتج.
    

### 🎯 CQ — التحكم بجودة NVENC

في NVENC نستخدم **CQ** بدل `CRF` المستخدم مع `libx264`.

كلما **قل الرقم** → جودة أعلى + حجم أكبر.

|CQ|الجودة|الحجم|
|---|---|---|
|18|عالية جدًا|كبير|
|20|ممتازة|كبير نسبيًا|
|**23**|**ممتازة + حجم مناسب ⭐**|متوسط|
|25|جيدة جدًا|أصغر|
|28|ضغط قوي|صغير|

### ⭐ القاعدة السريعة

```text
CQ 18 → جودة عالية جدًا
CQ 20 → جودة ممتازة
CQ 23 → أفضل توازن ⭐
CQ 25 → ضغط أكبر
CQ 28 → حجم صغير / جودة أقل
```

> **ملاحظة:** قيم CQ وCRF ليست متطابقة. `CQ 23` في NVENC لا تعني نفس الجودة أو الحجم تمامًا مثل `CRF 23` في x264.

## ⚙️ PRESET — سرعة وكفاءة NVENC

NVENC يستخدم Presets مختلفة عن `libx264`.

```text
p1
p2
p3
p4
p5
p6
p7
```

كلما اتجهت نحو `p7`:

→ الترميز يصبح أبطأ

→ يمكن الحصول على كفاءة ضغط أفضل عند نفس مستوى الجودة.

كلما اتجهت نحو `p1`:

→ الترميز يصبح أسرع

→ لكن كفاءة الضغط تكون أقل.

### ⭐ للاستخدام العادي

```bash
-preset p5
```

**P5** يوفر توازنًا جيدًا بين:

**السرعة + الجودة + حجم الملف**

### إذا كان الوقت غير مهم وتريد كفاءة أعلى

```bash
-preset p7
```

- `-b:a 128k` → جودة الصوت 128 kbps.
    
- `-movflags +faststart` → تحسين تشغيل MP4 عبر الإنترنت.
    

### ⭐ القاعدة السريعة


## ⚡ NVENC مقابل CPU

| |NVIDIA NVENC|CPU x264|
|---|---|---|
|الترميز|GPU|CPU|
|السرعة|⭐⭐⭐⭐⭐|⭐⭐⭐|
|استهلاك CPU|أقل|أعلى|
|كفاءة الضغط|جيدة جدًا|ممتازة|
|التوافق|يعتمد على Codec|ممتاز|
|الاستخدام|ترميز سريع|أفضل كفاءة ممكنة|

### ⭐ القاعدة السريعة

```text
سرعة الترميز → NVENC ⭐
أفضل كفاءة ضغط → x264
أقصى توافق → H.264
حجم أصغر → H.265 / HEVC
```

> **ملاحظة:** NVENC أسرع بكثير عادةً من الترميز باستخدام CPU، لكن الجودة والحجم عند نفس قيمة `CQ` ليست مطابقة تمامًا لـ `CRF` في x264.
